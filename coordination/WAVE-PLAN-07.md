## Plan summary

**Two work units, two sequential waves, two single-cluster dispatches.** WU-Phase3-2A (Google TPU/ICI adapter) and WU-Phase3-2B (live-fetch interface extension across 5 adapter sources) are split into Wave 7 and Wave 8 sequential single-cluster dispatches per **Option B** (split-with-sequential — recommended). Bundle (Option A) and parallel-cluster fan-out (Option C) were both evaluated and rejected — see Step 3 Judgment call 1.

**Fan-out analysis:**

- Parallel-cluster fan-out (Option C) is **structurally impossible**: WU-2B's scope per PRD line 480 ("extends Slurm/K8s/NVLink/Neuron/TPU adapters") includes the TPU adapter source that WU-2A creates. WU-2B cannot modify a file that does not yet exist. D1 HIGH dependency from WU-2A → WU-2B is the load-bearing structural constraint.
- Bundle into single WU-Phase3-2 cluster (Option A) is **technically possible** but architecturally weak: combines two distinct activities (novel-vendor adapter creation + cross-cutting interface refactor across 5 files) producing a cluster whose AC count (~28–36 estimated) exceeds the R20+R21 split-decision threshold (18 ACs). Strongest precedent is R20+R21 split (SLICE 2.A aggregator-contract + SLICE 2.B fleet-merge consumer) where two architecturally distinct activities in separate sequential rounds produced "clean separation of concerns" per PHASE-2-SLICE-2-CLOSE-WALK § 2.2. SLICE 2's split mirrors that shape exactly: 2A = vendor adapter creation (parallel-class with R28/R29/R30/R53); 2B = cross-cutting interface refactor across 5 files.
- Split with sequential waves (Option B; recommended) honors the structural D1 HIGH constraint cleanly + keeps each cluster within reviewable AC budget + lets WU-2A's Reviewer findings inform WU-2B's interface design.

**Trade-off framing:** fan-out is unavailable here — D1 HIGH from 2A → 2B forecloses Option C; AC-count + architectural-distinctness considerations favor split over bundle. Operator should NOT read "single-cluster waves" as fan-out-aversion; the D-test analysis at Step 2 + the R20+R21 precedent are the load-bearing reasoning.

### Judgment call 1 — SLICE 2 decomposition: bundle into single WU-Phase3-2 vs split into sequential WU-2A + WU-2B

- **Ambiguity:** PRD § Phase 3 SLICE structure SLICE 2 sub-section (lines 477–481) enumerates two distinct work units (WU-Phase3-2A Google TPU adapter + WU-Phase3-2B live-fetch interface design) with no operator pre-recorded bundle-vs-split conditional analogous to OQ-P3-10 (the Phase 3 SLICE 1 bundling condition). - **Candidate resolutions:**
  - **(a) Option B (split with sequential single-cluster waves; Coordinator's recommendation).** Wave 7 = WU-Phase3-2A standalone (Google TPU adapter; full tier; new vendor parallel-class with R28/R29/R30/R53 precedent). Wave 8 = WU-Phase3-2B standalone (live-fetch interface extension across 5 adapters; full tier; cross-cutting refactor). CLUSTER-HANDOFF-WAVE07-2A-2B.md emitted at WAVE-GATE-07 close per established Phase 2 wave-gate-emits-handoffs-for-wave-it-authorizes convention.
  - **(b) Option A (bundle into single WU-Phase3-2 cluster).** One Wave 7 cluster ships both TPU adapter creation + 5-adapter interface extension. Internal sequencing within the cluster (which scope ships first; whether AC enumeration covers TPU adapter ACs before interface-extension ACs) is the Architect's spec-time job. Operationally analogous to R52 WU-Phase3-1 bundled Trainium+Inferentia, BUT with one critical difference: R52 bundled 2 same-class WUs (both vendor adapter creation under one parallel-class pattern); SLICE 2 would bundle 1 vendor adapter creation + 1 cross-cutting interface refactor — two architecturally distinct activities, not one repeated activity.
  - **(c) Option C (parallel-cluster fan-out).** WU-Phase3-2A + WU-Phase3-2B in same wave with explicit CLUSTER-HANDOFF on shared surfaces. STRUCTURALLY IMPOSSIBLE — WU-2B's PRD-line-480 scope ("extends Slurm/K8s/NVLink/Trainium/TPU adapters") explicitly includes the TPU adapter that WU-2A creates. WU-2B cannot modify a file that does not yet exist. The D1 HIGH inter-WU edge (Step 2) is the load-bearing structural constraint that forecloses parallel dispatch. Rejected.
- **Claude's judgment:** Option (a) — Option B split with sequential single-cluster waves.
- **Reasoning:** Five factors favor split-sequential:
  1. **D-test reality forecloses fan-out (Option C structurally impossible).** WU-2B's modification of `engine/topology/tpu-source.ts` (a file WU-2A creates) cannot be parallel-dispatched with WU-2A's creation of that same file. Either WU-2B's TPU coverage drops out of scope (contradicts PRD line 480) or WU-2B sequences after WU-2A. The latter is the structurally-correct shape.
  2. **R20+R21 precedent — strongest match.** Phase 2 SLICE 2 split into R20 SLICE 2.A (VerdictGrouper aggregator-contract; ~15 ACs) + R21 SLICE 2.B (fleet-merge consumption layer; ~11 ACs). Both architecturally distinct activities (boundary change vs consumer layer); both ship in separate sequential rounds; PHASE-2-SLICE-2-CLOSE-WALK.md § 2.2 explicitly documents this split as successful ("Clean separation of concerns: R20 = aggregator-contract boundary; R21 = consumer layer. Two cleanly reviewable rounds vs one ~26-AC monster."). Phase 3 SLICE 2 has the same shape: 2A = vendor adapter creation (boundary/substrate); 2B = cross-cutting interface refactor across 5 files (consumer-layer-style cross-cutting work). The R20+R21 precedent is the strongest available match.
  3. **R52 bundling precedent does NOT apply here.** R52 bundled Trainium + Inferentia because both were the same architectural activity (parallel-class vendor adapter creation discriminated only by chip family) AND shared a D5-strict write-conflict on a single enum literal (`'neuron_link_peer'` applies to both chip families). Phase 3 SLICE 2's WU-2A + WU-2B are NOT the same activity (vendor adapter creation vs cross-cutting interface refactor) AND do NOT share a D5-strict (per Step 2 D5-LOW row: WU-2A adds enums; WU-2B is READ-ONLY on verdict.ts). Neither of R52's bundling conditions is satisfied.
  4. **AC count + reviewability budget favor split.** WU-2A frame-level AC target = 12–16; WU-2B frame-level AC target = 14–18. Bundled total = 26–34. This exceeds the R20+R21 split-decision threshold of 18 by a comfortable margin. Per PHASE-2-SLICE-2-CLOSE-WALK § 2.2 carry-forward observation ("Rounds with larger test matrices may still be cleanly reviewable if the ACs are tightly clustered in one file"), bundled SLICE 2 ACs would NOT be tightly clustered (they span TPU adapter + 5 distinct existing adapter modifications + 1 interface-design AC; 7+ files of test surface), so the bundled-but-clustered escape valve does not apply.
  5. **Sequential ordering creates a Reviewer-feedback loop that improves WU-2B quality.** WU-2A's Reviewer report will surface TPU-adapter-specific findings (interface conformance details, sparse-data handling patterns) that inform WU-2B's interface-design choices. Bundled dispatch loses this feedback loop. Sequential dispatch preserves it.
