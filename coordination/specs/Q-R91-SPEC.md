## § 1 Mechanism

### § 1.1 Resolution mechanism — Approach D (paths mapping + file: dependency + pretest builds engine/dist)

Selected per § A1 brainstorm; full why-picked/why-rejected at SPEC-AUDIT § A1.3 + § A4.

**Three concurrent surfaces materialize the resolution**:

1. **tsconfig.json `paths` mapping** — gives `tsc` (which uses legacy `moduleResolution: "node"` and does NOT respect package.json `exports` field per P0.5) a way to resolve `@johnpatrickwarren-oss/deploysignal-engine/<subpath>` at compile time. Mapping points to engine **source** files (e.g., `./engine/types/verdict`).
2. **Root package.json `dependencies` file: dep** — `"@johnpatrickwarren-oss/deploysignal-engine": "file:./engine"`. pnpm install (run once by Implementer after dep addition) creates a symlink at `node_modules/@johnpatrickwarren-oss/deploysignal-engine` → `./engine`. Node's module resolver finds the symlink; reads `engine/package.json`; honors `exports` field; resolves to `engine/dist/<subpath>.js`.
3. **`pretest` script extension** — root `package.json` `"pretest"` extends from `tsc -p tsconfig.test.json` to `tsc && tsc -p tsconfig.test.json`. The leading `tsc` (root project) builds `engine/dist/` (per R90 outDir). The second `tsc -p tsconfig.test.json` builds tests + tools + engine `.js` co-located with `.ts` (current behavior unchanged). This sequencing guarantees `engine/dist/*.js` exists before Node runtime imports resolve through the symlink + exports map.

### § 1.2 Why this works (dual-compile-mode coherence)

| Phase | Resolver | Path | Result |
|---|---|---|---|
| Compile time (tsc + tsconfig.test.json) | TypeScript paths mapping | `@johnpatrickwarren-oss/deploysignal-engine/types/verdict` → `./engine/types/verdict` (source) | tsc reads `engine/types/verdict.ts`; type-checks ✓ |
| Runtime (node --test) | Node `require` / dynamic import | `@johnpatrickwarren-oss/deploysignal-engine/types/verdict` → `node_modules/@johnpatrickwarren-oss/deploysignal-engine/dist/types/verdict.js` (via exports map) | Node executes `engine/dist/types/verdict.js` (built by leading `tsc`) ✓ |

Both resolution paths point at semantically-equivalent code (engine `.ts` source and its `.d.ts`/`.js` build output). Engine package.json `exports` map already enumerates all required subpaths per P0.1 + P0.13.
